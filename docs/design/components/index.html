Components

Nexwall Endpoint is composed of open-source building blocks and Nexwall's own code. The table shows what is used for what, and under which licence.

On the endpoint​

PartRoleOriginLicence
nx-agentEnrolment, policy, updates, spool, health, tamper resistance, response executorNexwall (Go)Proprietary
Windows sensorBehaviour telemetry and rules from Event Tracing for Windows, memory scanning, kill and isolateFork of FibratusApache-2.0
Linux sensorsRuntime detection and in-kernel enforcement through eBPFTetragon and Falco, packaged unmodifiedApache-2.0 (eBPF programs under GPL-2.0 or a permissive alternative)
macOS sensorExecution and file authorization; telemetry through Apple's Endpoint Security frameworkFork of Santa plus a Nexwall Endpoint Security clientApache-2.0
Inventory and huntingQueryable inventory and ad-hoc questionsosqueryApache-2.0
File integrity, configuration and vulnerability checksIntegrity, compliance baselinesWazuh agent, unmodified, separate processGPL-2.0
OS controlsManaged Microsoft Defender, application control, disk encryption and host firewall settingsOperating systemNot redistributed

Why these: each is mature, widely used and replaceable behind the same local interface, so no single project is a point of failure.

In the Controller service​

PartRoleLicence
Nexwall Endpoint Controller (Go)API, tenancy, policy, enrolment and certificate authority, response workflows, auditProprietary
PostgreSQLConfiguration and statePostgreSQL licence
NATSEvent bus between ingestion and the storesApache-2.0
OpenSearchSearch and detection storageApache-2.0
ClickHouseAnalytics and reportingApache-2.0
VectorEvent batching and routingMPL-2.0
TemporalDurable response workflowsMIT
LogtoSign-in for people (OpenID Connect)MPL-2.0
Wazuh managerIntegrity, compliance and vulnerability analysisGPL-2.0 and AGPL-3.0 for parts, used unmodified

The server-side set is the target design. The first releases start with a lighter set (PostgreSQL and NATS behind the same event model) and add the search and analytics stores as the product grows.

Detection content​

  • Rules on the endpoint come from the sensors' own rule sets and from Nexwall packs.
  • Correlation rules use the Sigma format.
  • Each rule keeps its author, source and licence, and the attribution is carried into every alert.

What Nexwall builds itself​

The agent, the Controller service, the event envelope and OCSF mappers, the policy and update system, the response logic and the detection packs. See Data model and Identity and tenancy.
